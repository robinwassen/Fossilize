## Problem

Pipeline replay and Vulkan device setup diagnostics discard raw failure results. Some compute and ray-tracing capture messages name the wrong pipeline type and speculate about unsupported pNext chains. Cache export errors lose the originating OS error during cleanup.

## What changes

- Preserve numeric VkResult, operation/phase and available pipeline hash or device context in replay/setup failures, including compile-required paths.
- Correct pipeline capture resource names across normal, QA, paranoid, eager and binary modes, and report unknown recording causes honestly.
- Snapshot errno at cache open/write/close failures before cleanup can overwrite it; distinguish pipeline and validation caches.
- Register GPU-independent tests through production replay, device and exported layer call paths, with successful controls and compatibility fixtures.

## Why this matters

Failure reports retain the evidence needed to distinguish controlled API errors, capture rejection and cache export failure without treating them as driver crashes or unsupported features.

## Why this approach

This is the initial diagnostic-context slice requested in #10. It retains public interfaces, Vulkan return/handle behavior and existing CLI exit policy while improving existing human diagnostics. It introduces no common result schema, process-controller redesign or persistence guarantee.
